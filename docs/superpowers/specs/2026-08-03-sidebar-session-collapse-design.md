# 左侧项目与工作区会话折叠设计

## 背景

左侧侧栏按项目展示会话。启用 Git 工作区后，项目内还会按本地工作区和沙盒工作区分组。会话数量较多时，列表会占用大量纵向空间，影响项目和工作区之间的快速切换。

现有 `SortableWorkspace` 已通过 `Collapsible` 和 `workspaceExpanded` 支持内部工作区折叠，但存在两个缺口：

- 最外层项目不能独立隐藏其下会话和工作区列表。
- 未启用 Git 工作区时，`LocalWorkspace` 直接展示会话，没有标题和折叠入口。

## 目标

- 每个最外层项目可独立展开或折叠其下全部会话内容。
- 每个内部本地或沙盒工作区可独立展开或折叠会话列表。
- 折叠状态在 OpenCode 重启后保留。
- 打开折叠区域中的会话时，自动展开所属项目和工作区并定位当前会话。
- 保持项目导航、会话排序、加载更多和工作区管理行为不变。

## 非目标

- 不改变会话数据、会话生命周期或服务端接口。
- 不改变项目和工作区排序。
- 不增加全局“全部展开/全部折叠”操作。
- 不因折叠关闭当前会话或取消后台任务。

## 交互设计

### 项目层

每个项目行增加独立的 chevron 图标按钮。项目名称和头像继续执行现有项目导航，chevron 仅控制会话区域可见性。

- 展开时图标指向下方，tooltip 和 `aria-label` 为“折叠会话”。
- 折叠时图标指向右侧，tooltip 和 `aria-label` 为“展开会话”。
- 按钮设置动态 `aria-expanded`。
- 点击按钮时阻止事件冒泡，避免触发项目导航、拖拽或菜单。
- 首次出现的项目默认展开。

项目折叠后隐藏：

- 未选中项目下方的会话预览。
- 选中项目的完整会话列表。
- 选中项目内的本地和沙盒工作区列表。

项目行本身、工作状态和项目操作菜单保持可见。

### 工作区层

启用 Git 工作区时，继续使用现有 `SortableWorkspace` 标题和折叠行为。

未启用 Git 工作区时，`LocalWorkspace` 增加与现有工作区一致的本地工作区标题和 `Collapsible` 容器。标题展示本地工作区类型、分支或目录名以及 chevron，下面包裹原有 `WorkspaceSessionList`。

用户可以手动折叠当前会话所在项目或工作区；当前页面不受影响。再次导航到该区域中的会话时自动展开。

## 状态模型

在 `layout.tsx` 已持久化的侧栏状态中新增：

```ts
projectSessionsCollapsed: Record<string, boolean>
```

键使用项目根目录经 `pathKey` 规范化后的值。缺失键等价于 `false`，即项目默认展开。

内部工作区继续使用现有 `workspaceExpanded`：

- 缺失键时，本地工作区默认展开。
- 沙盒工作区沿用当前默认策略。
- `LocalWorkspace` 和 `SortableWorkspace` 使用同一状态来源。

不复用 `LocalProject.expanded`。该字段控制项目集合和加载语义，与会话列表可见性职责不同。

## 组件边界

### `layout.tsx`

- 提供项目会话折叠状态读取和切换方法。
- 使用规范化项目路径作为持久化键。
- 在会话导航时自动展开所属项目和工作区。
- 将能力通过现有 sidebar context 传递给项目和工作区组件。

### `sidebar-project.tsx`

- 在 `ProjectTile` 操作区渲染独立折叠按钮。
- 在 `SortableProject` 中根据项目折叠状态控制会话预览和完整内容的挂载。
- 不直接管理持久化状态。

### `sidebar-workspace.tsx`

- 保留 `SortableWorkspace` 现有折叠实现。
- 为 `LocalWorkspace` 增加标题和 `Collapsible` 包装。
- 复用 `WorkspaceSessionList`，不复制会话加载和渲染逻辑。

## 数据流

1. 用户点击项目 chevron。
2. 项目组件调用 context 的切换方法。
3. `layout.tsx` 更新 `projectSessionsCollapsed[pathKey(root)]`。
4. 持久化层保存状态，项目组件响应式隐藏或显示内容。

打开会话时：

1. `syncSessionRoute` 解析会话目录所属项目根目录。
2. 将对应项目的折叠状态设为展开。
3. 将对应 `workspaceExpanded[directory]` 设为 `true`。
4. 执行现有会话 viewed 标记和 `scrollToSession` 定位。

## 边界行为

- 项目关闭后保留其折叠记录；再次添加相同路径的项目时恢复用户选择。
- Windows 路径大小写或路径分隔符差异由 `pathKey` 统一处理。
- 折叠不清空会话缓存，不改变 `limit`，重新展开后恢复原列表和“加载更多”状态。
- 会话正在运行时允许折叠，工作状态指示仍显示在项目行。
- 移动端和桌面端共享状态，按钮保持可触摸和键盘访问。

## 测试策略

### 单元测试

- 未记录状态的项目默认展开。
- 不同项目的折叠状态相互独立。
- 等价路径使用同一持久化键。
- 打开会话时自动展开所属项目和工作区。
- 用户手动折叠不改变当前会话路由。

### 组件与回归测试

- 点击项目按钮隐藏会话内容，再次点击恢复。
- 点击项目折叠按钮不触发项目导航。
- 本地工作区和沙盒工作区可独立折叠。
- 刷新应用后恢复折叠状态。
- 导航到折叠工作区中的会话后自动展开并显示当前会话。
- 折叠和展开后“加载更多”、工作状态和项目菜单仍可用。

## 验收标准

- 用户可在左侧对每个项目和每个内部工作区独立展开或折叠会话。
- 折叠状态重启后保持。
- 打开隐藏会话时对应层级自动展开。
- 项目导航、会话导航、加载更多和工作区操作无行为回归。
- app 类型检查、相关单元测试和侧栏回归测试通过。
